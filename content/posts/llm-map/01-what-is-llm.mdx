周一早上的全员会，老板周总把「AI 提效」写进了知了云年度 OKR 的第一行，顺手又加了一条：给产品加个「AI 助教」功能。散会时他在走廊拦住你：「你懂技术，调研一下大模型，月底给管理层讲讲，这东西能帮我们干什么。」

知了云是一家 50 人的企业培训 SaaS 公司，你是这里的全栈开发。答应完回到工位，客服组的小陈先凑过来问了一个问题：「我们要上 AI 客服的话，它回答学员的问题，会瞎编吗？」

你张了张嘴，发现答不上来，最后只能说「应该……不会吧」。但你自己都不信这句话——上个月你让 ChatGPT 查一个 npm 包的配置项，它一本正经地写了一个根本不存在的选项，你还真去试了，报错才反应过来。

写代码、改周报、润色邮件，你天天用它。但「它到底是什么、为什么会一本正经地胡说」，你确实说不清。调研的第一课，先补给自己。

## 它做的所有事，都从一次接龙开始

给它半句话：「今天天气真」。它接：「好」。

把接完的新句子喂回去：「今天天气真好」。它接着接：「，适合出门散步」。

ChatGPT、DeepSeek、Claude，所有大模型的核心动作就这一个：**读一段文字，预测下一个最小单位是什么**。写周报、改代码、答学员问题，全部是这个动作重复成千上万次的结果——接一个词，拼回句子，再接下一个，直到它判断话说完了。

这个「最小单位」叫 **token**。它不是字也不是词，是模型自己切出来的文字碎片：英文里一个长单词可能拆成两三块（unbelievable 拆成 un / believ / able），中文一个汉字通常要占一到两个 token——大部分模型的词表是英文优先的，所以同样的内容，中文比英文更「费」token。你在输入框里敲的每句话、它吐出来的每个回答，在模型眼里都是一串 token。

一个自然的问题冒出来：接龙这么蠢的游戏，怎么会接出「智能」？

## 为什么接龙能接出「智能」

想象一个神童，把人类公开写过的文字几乎全读了：网页、书籍、论文、论坛吵架、几千万个代码仓库。然后你天天考他接话。

「这道菜好吃的秘诀是」——要接得像，他得懂菜谱的逻辑。

「for i in range(」——要接得对，他得懂 Python 的语法。

「对不起，我不是故意的，」——要接得妥，他得懂道歉的分寸。

关键在于：没有任何人写过你正在问的这句话，所以光背原文没用。要把所有的「下文」都接得像模像样，他必须把语言里**重复出现的规律**吃透——语法、常识、逻辑、代码的写法、情绪的分寸。

大模型训练干的就是这件事：把互联网级别的文本灌进去，让模型一遍一遍练「接下一段」，练到猜得足够准，再把猜中的规律压缩存进模型的**参数**里。注意，存的不是原文——整个互联网存不下，存的是规律的压缩。所以它不是「背过答案」，是「学会了像」。

这一步在业界叫**预训练**（pre-training）。后面所有让你惊艳的能力——写文案、翻译、改代码——都是这一步的副产品。

## 「大」是多大

GPT-3 有 1750 亿个参数；人脑约有 860 亿个神经元。这两个数字不能直接划等号（参数不是神经元，运作机制完全是两回事），但数量级可以感受一下：这是一个和人脑同一量级的东西，跑在几万张显卡上。

训练一次的成本是千万美元级——电费、显卡、数据清洗，烧的都是真金白银。所以才有「大模型」这个名字，大在三个地方：**参数大、数据大、算力大**。这也是为什么全世界能从零训练大模型的公司只有一小撮，其他人都是在用它们的成品。

顺便说个背景：2018 年前后，业界下了一个赌注——「把接龙模型越做越大，能力会出现质变」。当时不少人觉得荒唐，接龙就是接龙，怎么会接出智能。GPT-3 出现后赌局开始明朗，2022 年底 ChatGPT 上线，算是「赌赢了」的公开演示。这也是本篇标题的来历。

## 它怎么变得「听话」

预训练刚结束的模型其实很难用。你问它「怎么申请退款」，它可能给你接一段像模像样的退款小说——因为它只会接话，没学过「当助手」。

所以出厂前还有第二步：**对齐**（alignment），最常听到的实现方式叫 RLHF——基于人类反馈的强化学习。粗糙但准确的版本是：雇一批人来调教，写出「好回答」的示范，再给模型的 各种回答 打分——有用、诚实、无害的得分高。模型朝着高分方向调整，慢慢学会了先列步骤再给答案、学会了说「我不知道」。

但注意一个细节：它学会的是「更常说不知道」，不是「永远不会编」。这个细节先记着，下一篇会反复用到。

## 它和搜索引擎，差在一个根本点上

小陈的问题、你被 npm 配置坑的那次，根源都藏在这张表里。

|              | 搜索引擎                     | 大模型                               |
| ------------ | ---------------------------- | ------------------------------------ |
| 干活方式     | 从已有网页里**检索**         | 一个 token 一个 token **生成**       |
| 答案从哪来   | 别人写好的，本来就存在于某处 | 现场写的，可能从来没人写过           |
| 错起来什么样 | 搜不到，至少你知道没搜到     | 一本正经地编，你未必看得出           |
| 擅长的活     | 有标准答案的查找             | 没有现成答案的活：写、改、总结、翻译 |

这是整个系列的地基：**大模型不查资料，它现场写**。写一封没人写过的道歉信，靠的是这个；编一条不存在的退款政策，也是这个。创造力和幻觉是同一个能力的两面，切不开。后面两篇会把这一面展开成一张「什么活能交给它」的判断表。

## 一张名词卡片

调研笔记的第一页，把这一堆名词一次钉清楚：

| 名词                           | 一句话说明                                                                                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 大模型 / LLM                   | Large Language Model，大型语言模型，本系列主角                                                                                                   |
| GPT                            | Generative Pre-trained Transformer，「生成式预训练模型」——这名字本身就在说「预先训练的接龙机器」，同时是 OpenAI 的产品线名                       |
| Claude / Qwen / DeepSeek / GLM | 另外几家的对话大模型：Anthropic、阿里通义千问、深度求索、智谱                                                                                    |
| 开源 vs 闭源                   | 开源 = 模型权重公开，能下载到自己服务器部署（DeepSeek、Qwen、Llama）；闭源 = 只能通过官方接口使用（GPT、Claude）。开源不等于免费商用，要看许可证 |
| 基座模型 vs 对话模型           | 基座 = 预训练完的毛坯，只会接话；对话模型 = 对齐之后你能直接用的成品                                                                             |
| 参数                           | 模型里存放规律的「旋钮」，1750 亿个参数就是 1750 亿个旋钮                                                                                        |
| 上下文窗口                     | 一次对话里模型能「看得见」的文字长度上限，超了就忘，第 5 篇细讲                                                                                  |

## 它不是什么

给管理层的汇报，你打算先放这三个「不是」——因为不懂技术的人最容易在这三件事上想歪：

**它不是数据库。** 你没喂给它的东西，它就没有。学员名单、订单记录、去年的财报，它统统不知道。别指望「AI 什么都记得」。

**它不是搜索引擎。** 默认情况下它不联网，训练数据有截止日期，之后的世界它一无所知。现在部分产品加了联网搜索，那是给模型外挂了一个检索工具——外挂的事第 3 篇讲。

**它不是程序。** 它不执行逻辑，不做精确计算。让它算一笔复杂的账，它是在「猜下一个数字长什么样」，不是在算。财务的活别交给它。

## 先把它当个「人」用

回到小陈的问题，你现在能给出负责任的回答了：AI 客服会瞎编吗？——会。因为它的工作方式就是「现场写一个最像答案的回答」，写得像和写得对是两回事。想让它少编，得给它喂真材料（怎么喂，第 3、5 篇讲）。

一个顺手的定位：**把它当一个读过所有书、见多识广、但会一本正经胡说的顾问**。语言类的活——写、改、总结、翻译——放心找它；事实和数字，盯紧它；精确计算和内部数据，别指望它。

「哪些活能交给它、哪些会翻车」，这个判断不该靠感觉。下一篇先做个实验：把知了云的五条业务线挨个丢进 ChatGPT，结果一半惊艳一半翻车——而所有原因，都藏在「接龙」这个本质里。
