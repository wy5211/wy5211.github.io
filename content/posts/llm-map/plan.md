# 大模型认知地图 系列计划

## 背景

### 为什么写这个主题

ChatGPT 火了三年多，Cursor、DeepSeek、Agent 这些词天天在眼前晃，但真被问一句「大模型到底是什么」，多数开发者（包括我）只能给出模糊的回答——「就是很厉害的 AI」。会调用 API 不等于理解这东西；看新闻「XX 公司 AI 提效 30%」也无法判断是真是假、对自己有什么影响。

这个系列要回答五个真实困惑（来自原始需求原话）：

1. 大模型是什么
2. 可以解决什么问题
3. 应用场景是什么
4. 雇主通常用大模型处理什么东西
5. AI 时代，还有必要学习大模型吗

**刻意不深入**：不讲 Transformer 结构、不讲数学、几乎无代码。目标是建立认知地图——每个名词（token、幻觉、RAG、Agent、微调、开源模型）钉在它该在的位置上，看完能对任何 AI 新闻做出自己的判断。

- 文章类型：A 的扫盲/地图变体（同 infra-map 模式）+ E 的职业视角
- 与 infra-map 同款方法论：**不教操作，讲「每个名词回答了什么问题」**；但叙事不是「被问题逼出来的演进链」，而是「一个裸模型 + 几种外挂 = 所有 AI 应用」的拆解视角

## 主线场景：知了云的 AI 调研任务

**知了云**：一家 50 人的企业培训 SaaS 公司。你（读者代入）是公司的全栈开发。年初，老板把「AI 提效」写进公司 OKR，还想给产品加个「AI 助教」功能，然后在周会上点名：「小王你懂技术，调研一下大模型，月底给管理层讲讲能用它干什么。」

这个系列就是你的调研笔记。公司五条真实业务线，每篇都在它们身上做判断：

```
1. 客服   —— 学员问题 70% 重复（退款、有效期、发票），3 个客服每天 400+ 条
2. 内容   —— 运营每周写 8 篇课程介绍 + 投放文案
3. 销售   —— 要读客户 30 页的招标文件，提炼需求要点和预算
4. 研发   —— 20 万行老代码，文档缺失，新人上手慢
5. 行政   —— 每周 3 场会议纪要，合同初审
```

场景演进：01 用客服话术演示「文字接龙」是什么 → 02 拿五条业务逐个判断能不能交给模型（哪些会翻车）→ 03 发现市面上 AI 产品其实只有五种形态，知了云 AI 助教属于哪种 → 04 用公开企业案例对照，看雇主真金白银买的是哪几类用途 → 05 运营被老板骂「文案一股 AI 味」，你教她最小使用知识 → 06 调研收官：给老板的三页汇报 + 回答自己「要不要学、学到哪层」。

## 每篇文章大纲

### 01 大模型到底是什么：一台赌赢了的文字接龙机器

- 学习目标：能给别人讲清楚 ChatGPT 输入框背后是什么、和搜索引擎的本质区别
- 核心问题：它是什么？不是什么？为什么「大」？
- 主线场景：客服同事问你「AI 客服能保证答案正确吗」，你发现自己答不上来——因为从没搞懂它内部怎么工作
- 内容要点：
  - 文字接龙（下一个 token 预测）：token 是什么（中文一个字约 1-2 token）；从接一个词到接出一整段
  - 为什么接龙接出「智能」：读完了几乎整个互联网的文本，把语言规律和知识压进了参数——不是检索是生成
  - 大在哪：参数量数量级直觉、训练成本直觉（千万美元级）、训练一次=烧掉一个小公司
  - 怎么变听话：预训练（读全网）→ 对齐/RLHF（一句话：人类反馈教它好好说话）
  - 和搜索引擎的本质区别：查已有的 vs 逐字生成没有的——这既是创造力的来源，也是幻觉的伏笔（预告 02）
  - 名词卡片：大模型/LLM/GPT/Claude/Qwen/DeepSeek、开源 vs 闭源、基座模型 vs 对话模型
  - 它不是什么：不是数据库（不存你的文件）、不是搜索引擎（默认不查网）、不是程序（不会精确算账）
- 与前篇关联：系列首篇，用「答不上客服同事的问题」开场
- 结尾 trade-off：什么时候把它当「一个读过所有书的人」用正好、当搜索引擎用必翻车；埋 02——能接话不等于接得对

### 02 能力与边界：什么活能交给它，什么活它会翻车

- 学习目标：拿到任何具体任务，能用一套三问框架判断该不该交给大模型
- 核心问题：为什么它写文案惊艳、算账却错得离谱？幻觉能修干净吗？
- 主线场景：你把老板的五条业务挨个丢给 ChatGPT 试——客服话术像模像样、文案能改到能用、标书要点提炼得不错；问它「知了云去年营收」它编了个数字、算退税算错了
- 内容要点：
  - 它擅长的四类：语言转换（写/改/缩/扩/译/换语气）、结构化抽取（从标书抽预算工期）、代码（训练数据多+错了能跑出来验证）、头脑风暴
  - 必然翻车的四类 + 从「接龙」本质推导原因：幻觉（默认动作是编一个像的，不是承认不知道）、精确计算（在猜数字的下一个字符）、实时/私有信息（训练数据有截止日）、长链条任务（每步 95% 正确，10 步链下来只剩 60%）
  - 幻觉专题：为什么修不干净（是能力的代价不是 bug）；一线对策（喂原文让它只做摘要、要求「不知道就说不知道」有用但不彻底、关键事实必须人工复核）
  - **三问判断框架**（全系列第一个方法论，04 篇企业视角会回收）：错了能发现吗（可验证性）？错了代价大吗（容错度）？输入输出是文本吗（模态）？
  - 用框架给知了云五条业务出第一版判断表（04 篇用真实企业案例修正这张表）
- 与前篇关联：01 讲了「生成而非检索」的本质，本篇从本质推导出边界
- 结尾 trade-off：五条业务哪些立刻能上、哪些绝不能上、哪些要加人工环节；埋 03——单件事判断完了，落到产品上到底长什么形态

### 03 应用场景地图：所有 AI 产品只有五种形态

- 学习目标：看到任何新 AI 产品，30 秒内判断它是哪种形态、给了模型什么外挂
- 核心问题：智能客服、Cursor、Perplexity、Midjourney……它们背后是不是同一个东西的不同包装？
- 主线场景：老板甩来三篇文章让你「都研究下」，你越看越乱，直到画出一张图：一个裸模型 + 四种外挂 = 市面上所有 AI 应用
- 内容要点（地图主体，一个裸模型 + 四种外挂 = 五种形态）：
  1. 裸对话：ChatGPT / DeepSeek 网页——人直接用模型，个人提效主力
  2. 给知识（RAG）：模型 + 你的文档检索——智能客服、企业知识库、知了云 AI 助教就是它；一句话讲清为什么存在（02 说过它没见过你的文档 → 先检索再喂给它）
  3. 给工具（Function Calling / Agent）：模型 + 可调用的 API——查订单、操作系统；Agent = 模型 + 工具 + 循环，让它自己干多步
  4. 嵌进软件（AI 功能化）：Cursor / Copilot / Notion AI / 会议纪要——模型藏在功能按钮后面，用户未必感知
  5. 换模态：文生图（Midjourney）、语音、视频——同一种接龙，接的是图像/音频 token
  - 每种形态讲三件事：一个最熟的产品例子、它补上了裸模型的什么缺陷、知了云哪条业务对应
  - 这张地图的用法：新 AI 产品出现先问「哪种形态、什么外挂」
- 与前篇关联：02 判断了「哪些活可以交给它」，本篇回答「交给它之后产品长什么样」
- 结尾 trade-off：形态越往后工程越重越贵，个人和小公司从 1、2 起步；知了云该先做哪个；埋 04——形态说清了，公司花钱买的到底是哪几个

### 04 雇主拿大模型干什么：公司花钱的真实用途

- 学习目标：说清公司用大模型的六类真实用途；能解码 JD 里「AI 相关要求」的三层含义
- 核心问题：招聘 JD 里「会用 AI」到底指什么？哪些岗位的活在被拿走、哪些更值钱？
- 主线场景：调研中期，你去招聘网站翻了 50 条 JD，发现「AI 要求」其实是三种完全不同的东西混在一起写；对照之下，知了云的五条业务该往哪类用途上靠也清楚了
- 内容要点：
  - 雇主六类真实用途（每类配公开案例 + 数据，沿用 frontend-to-ai 的来源分层原则：硬证据/观察性统计/利益相关方信号/佐证，逐条标口径）：
    1. 写代码：Copilot / Cursor / Claude Code；GitHub 对照实验（任务完成快约 55%）、Google「新代码超 25% 由 AI 生成」（CEO 公开口径）
    2. 客服：Klarna 案例（承接 2/3 会话、相当于数百人客服——重点讲它后来的回撤，教读者「AI 落地数据要听下文」）；国内大模型客服现状
    3. 内容生产：营销文案、商品描述、SEO；电商与游戏美术的冲击
    4. 文档与知识：会议纪要、合同初审、内部知识库问答
    5. 数据结构化：标书/发票/简历抽取——最不性感但 ROI 最稳的一类
    6. 产品本身加 AI：SaaS 加 AI 助手成标配（正是知了云老板想干的）
  - JD 三层解码：会用 AI 工具（所有岗位）/ 会做 AI 应用（工程岗：API、RAG、Agent）/ 会研究模型（算法岗：训练微调，少数人）
  - 雇主的算盘：成本 × 可验证性——回收 02 篇的三问框架，用企业视角复用（系列内呼应）
  - 对人的影响：重复性低容错的活被拿走；定义问题、验证结果、把 AI 组合进流程的活更值钱
- 数据规范：写作时用 WebSearch 核实关键数字与出处，正文逐条标注来源与口径；找不到可靠出处的降级为定性表述，不编数字
- 与前篇关联：03 讲了产品形态，本篇讲公司实际上买哪几种（结论：六类用途集中在形态 2、3、4）
- 结尾 trade-off：六类用途按「增强人/替代人」分——增强类先落地，替代类集中在低容错高重复；知了云的第一版落地清单；埋 05——老板追问「那我们的人要不要培训」，先用明白，下一篇给使用者的最小知识

### 05 用好它的最小知识：提示词、上下文与成本

- 学习目标：不写一行代码，把模型当工具用到 80 分；听懂 token、上下文窗口、温度这些词
- 核心问题：为什么同一个模型，有人用得飞起、有人觉得「也就那样」？差距在使用方法
- 主线场景：运营用 ChatGPT 写的文案被老板骂「一股 AI 味」来找你求助；你看了她的输入框，只写了五个字「帮我写个文案」——问题不在模型
- 内容要点：
  - 提示词不是玄学，是把需求说清楚：背景/任务/要求/示例 四件套；同任务差提示 vs 好提示的输出对比演示（知了云课程文案实战）；角色扮演有用但别迷信
  - 上下文窗口：为什么聊久了它会「失忆」（记不下就滑出窗口）；长文档塞进去中间内容容易被忽略；该开新会话就开新会话
  - 模型选择与温度的日常直觉：大模型贵而稳、小模型快而便宜；随手问用小档、重要方案用大档
  - 成本直觉：token 计费、输入便宜输出贵；一次长对话几毛到几块钱；公司 API 账单为什么会爆炸（映射 03 的形态越往后越贵）
  - 三个高频词一句话分辨：提示词（教它做事）/ 微调（改它脑子）/ RAG（给它资料）——什么场景用哪个，回收 03 篇
  - 顺手破谣：「AI 味」的本质是输入太笼统，输出只能笼统
- 与前篇关联：04 结尾老板问「要不要培训」，本篇就是培训大纲
- 结尾 trade-off：这五样学到手够把模型用到 80 分，再多对非开发者是边际递减；再往上是应用开发的事；埋 06——会用之后，最后一个问题：要不要系统学

### 06 AI 时代还要不要学大模型：一个分层的答案

- 学习目标：把「学大模型」拆成三层，判断自己该停在哪层；能识破 AI 学习焦虑营销
- 核心问题：「学大模型」到底指什么？现在开始晚不晚？什么可以不学？
- 主线场景：调研收官，你给老板交三页汇报（是什么 / 能干什么 / 知了云怎么走），汇报全文在篇中呈现——它就是全系列的浓缩输出；PPT 最后一页是老板的问题「我们要不要组织学习？」，回答它之前你先回答了自己
- 内容要点：
  - 先拆问题：「学大模型」是三层完全不同的事——
    - L1 会用：提示词 + 场景判断 + 三问框架（即 05 篇内容），约 20 小时投入，回报立竿见影；正在从加分项变成基本盘（类比：会搜索、会 Office）
    - L2 会做应用：调 API、RAG、Agent 工程——开发者的清晰红利，正在从稀缺变标配（交棒 ai-fullstack / langchain 系列，附链接）
    - L3 会训练/研究模型：预训练、微调、对齐——少数人的全职职业（数学+算力+数据工程），转行成本极高，别被焦虑营销带偏
  - 回答原始问题：2026 年这个问题已不是「学不学」而是「学到哪层」；给出普通开发者的性价比排序
  - 什么保值 / 什么贬值：场景判断、验证能力、把 AI 组合成产品的工程感保值；具体模型操作细节、提示词套路贬值快
  - 诚实的一面：什么情况可以真的不学（L1 都用不上的工作），焦虑该省就省
  - 收官呼应：回到 01 篇那个「被客服同事问住」的瞬间
- 与前篇关联：全系列收官，五篇的问题在这里汇总成一份可用的汇报
- 结尾 trade-off：三层的时间投入/回报/适合人群一张表；三条下一步路线（日常够用 → 停在 L1；想做东西 → ai-fullstack；前端转岗细节 → frontend-to-ai）
