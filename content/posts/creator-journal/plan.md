# 程序员自媒体实战日志系列计划

## 背景

- **为什么写这个主题**：social-media 系列（15 篇）把各平台的规则、算法、投流方法论梳理完了，但那是「别人的地图」。缺一份自己的实战记录——像 investing-journal 之于投资：方法论看遍了，真正值钱的是自己的决策日志。这个系列就是那份日志。
- **核心话题**：账号定位、内容生产管线、数据看板、平台策略、AI 工作流、复盘迭代
- **文章类型**：E（生活/运营类）+ journal 体（滚动更新）
- **⚠️ 本系列的特殊性——不能批量写作**：journal 的价值在真实数据。开篇（01）现在写：实验设计、系统搭建、指标基线——这些是真实可写的（博客本身就是现成的内容资产和生产管线）。后续篇章随实践推进逐步写：有了一个月的真实数据写 02，跑通一次跨平台分发写 03……**写在前面的数据都是假的，这个系列必须慢慢长出来。**

## 01 开篇：实验设计与系统搭建（本次写）

- **学习目标**：定义这个实验的目标、约束、度量体系
- **核心问题**：一个全栈开发者做自媒体，到底在验证什么假设？怎么算成功、怎么算失败？
- **主线场景**：盘点手上的真实资产：一个跑了多年的技术 + 投资博客（40+ 系列、几百篇文章）、一套 Claude Code 的写作管线、15 篇方法论笔记——起点比大多数人好，为什么还是没做起来
- **内容要点**：
  - 假设清单：把 social-media 方法论里最想验证的 3-5 条写成可证伪的假设（如「长内容平台（公众号/知乎）适合存量博客的分发」「程序员受众的内容护城河是真实性而非技巧」）
  - 度量体系：北极星指标选什么（不是粉丝数——阅读完成率/订阅转化/互动率的取舍）、护栏指标（生产成本、时间投入上限——minimalism 约束：每周不超过 X 小时）
  - 实验设计：平台选择的决策记录（为什么先做 A 不做 B）、内容原子化策略（一篇长文 → 多平台素材的拆分规则）
  - 基线：当前博客的真实数据快照（文章数、访问量级、已有分发渠道）——所有后续对比的基准点
  - 失败条件：预先写好「什么情况下停止这个实验」——journal 的纪律（呼应 investing-journal/01：纪律比策略重要）
- **与前篇关联**：全系列唯一现在能写的——因为它写的是「开始」本身

## 系列节奏规划

- journal 体：每篇记录一段真实周期，写于周期结束后（数据在手再写）
- 每篇固定四段：这个周期做了什么决策 → 数据发生了什么 → 方法论哪条被验证/证伪 → 下个周期的调整
- 与 investing-journal 共享写作纪律：记录当时的思考原貌，复盘时不修改决策记录、只追加结论
- 后续篇章的触发条件写在 01 篇结尾，到点检查数据、动笔
