# Java 后端技术地图：从 Spring Boot 到微服务

## 背景

本系列是**扫盲/地图型系列**：面向正在学 Spring Boot、听说过分布式事务/微服务/MQ/Spring Cloud 等名词、但不知道它们之间是什么关系的读者。目标不是深入掌握每个技术，而是建立**名词 → 解决什么问题 → 主流框架是什么 → 和 Spring Boot 什么关系 → 什么时候不需要它**的完整认知地图。

与已有系列的关系：本系列是**横向串联的入口和索引**，纵向深入交给已有系列（`springboot`、`redis`、`java`、`mybatis`、`docker`、`devops`），每篇结尾设"深入阅读"环节互链。

**核心叙事**：这些名词不是并列的知识点，而是一条"演进补丁链"——每个技术都是为了解决上一个阶段的新问题。系列按流量增长的故事线组织。

**技术栈**：Spring Boot 3.x | Java 17 | Spring Cloud Alibaba | Nacos | OpenFeign | Gateway | Sentinel | RocketMQ | Seata | Redis | MySQL

## 写作规范

- 从具体业务问题/故障场景开头，禁止"本文将介绍..."
- 代码占比 < 25%，只放关键片段（3-5 段短代码），重概念轻实现，每段代码有引导语和解读
- 每篇包含**名词卡片**表格：本领域周边名词一网打尽（中英文 + 一句话定义）
- 每篇回答四个问题：什么问题逼出了这个技术 → 主流框架有哪些怎么选 → 在 Spring Boot 里长什么样 → 什么时候**不需要**它（反过度设计视角）
- 结尾是 trade-off 分析 + "深入阅读"（指向已有系列），不是复选框总结
- 贯穿案例从第 1 篇就开始（ShopLite 迷你电商的演进）

## 贯穿案例：迷你电商 ShopLite 的演进

用"下单"这一条核心业务线，讲述一家电商从单体到微服务的完整演进：

```
User:    id, username, passwordHash, balance（余额）
Product: id, name, price, stock（库存）
Order:   id, userId, productId, quantity, amount, status(待支付/已支付/已取消)
```

演进主线（与文章目录一一对应）：

```
阶段 0：单体 Spring Boot ShopLite（订单+商品+用户 一个应用 + 一个 MySQL）
阶段 1：流量涨 → 集群 + Nginx → 登录态丢失 → Redis / JWT        （02 篇）
阶段 2：数据库成为瓶颈 → 缓存 / 读写分离 / 分库分表              （03 篇）
阶段 3：代码膨胀、团队协作困难 → 拆微服务                        （04 篇）
阶段 4：拆完后的一系列新问题 → Spring Cloud 全家桶逐个登场        （05-09 篇）
阶段 5：可观测性与运维 → 链路追踪 / 日志 / K8s                   （10 篇）
收官：一个"下单"请求的完整旅程串起全部名词                        （11 篇）
```

## 预期效果

完成本系列后，读者将能够：

1. 听懂任何后端技术名词，并准确说出它解决什么问题、属于演进链哪一环
2. 画出一家公司从单体到微服务的完整技术架构图，解释每个组件存在的原因
3. 做出合理的技术选型判断（什么时候该用、什么时候属于过度设计）
4. 知道下一步深入学什么（通过互链进入已有专项系列）
5. 应对面试中"为什么用 X 不用 Y"类的架构问题
