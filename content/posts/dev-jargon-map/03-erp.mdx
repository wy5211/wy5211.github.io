上篇结尾，三只小鹿的仓库炸了：账面 1200 箱坚果，实际盘点 900 箱。更麻烦的是账不止两本——采购一本账（进了多少货、欠供应商多少钱），销售一本账（出了多少货、客户还欠多少钱），财务一本账（现金流到底什么样），月底对账像三方会谈，每次都谈崩。

先别急着请出 ERP。这个体量的公司，市场上会给它推荐一个更小的东西。

## 进销存：小公司的救命稻草

「进销存」这个名字实在得不像黑话：**进货、销售、库存**，三件事一本账。采购入库登记一笔，销售出库扣一笔，库存自动算出来——这解决了三只小鹿最痛的问题：至少「货」这一头的数字变成一本账了。

几百块一年的 SaaS 进销存（聚水潭、管家婆这类）多如牛毛，小卖部到中小电商都在用。它是很多老板接触的第一个「系统」，也是理解 ERP 的最佳起点——**ERP 就是进销存的完全体**。

完全体完全在哪？看一张订单在三只小鹿的进销存时代要走多少个系统：

```
天猫订单 → 进销存扣库存、记销售收入
开发票   → 财务的 Excel 手工记一笔
采购补货 → 进销存记采购，付款申请走微信审批
月底对账 → 三个系统（进销存 + 两本 Excel）人工核对
```

数据在系统之间靠人肉搬运，搬运就会出错、延迟、对不上。完全体的思路简单粗暴：**把公司的钱、货、人、流程全部塞进一个系统，一本账记到底**。

## ERP 模块地图：一张订单的全程旅行

ERP（Enterprise Resource Planning，企业资源计划）按职能拆成模块，模块之间共享同一套底层数据。跟着三只小鹿的一笔企业团购订单走一遍：

```
销售模块：客户下单，生成销售订单（客户：某互联网公司，年货礼盒 500 份）
    ↓ 自动检查
库存模块：现货只有 300 份，缺 200
    ↓ 自动生成
采购模块：向供应商下采购单，买齐原料
    ↓ 收货入库
库存模块：库存补足，触发发货
    ↓ 自动生成
财务模块：应收账款挂账 → 收到回款核销 → 成本利润自动结算
```

注意箭头里没有一个是人。**一笔业务从下单到利润，全程在一套数据上流转**——这就是 ERP 的灵魂，术语叫「业务财务一体化」：业务动一下，账自动跟上。财务月底不用对账，因为从头到尾只有一本账。

为了这本书账，ERP 的模块清单大致是：

| 模块     | 管什么               | 三只小鹿的对应场景            |
| -------- | -------------------- | ----------------------------- |
| 财务     | 总账、应收应付、成本 | 自动对账，告别三方会谈        |
| 采购     | 供应商、采购单、入库 | 补货申请变成正式采购单        |
| 库存     | 出入库、盘点、库龄   | 1200 还是 900，一键见分晓     |
| 销售     | 客户、报价、订单     | 企业团购的合同和账期          |
| 生产     | 生产计划、物料清单   | 第 06 篇自建工厂后登场        |
| 人事薪酬 | 员工、工资           | 通常和第 07 篇的 HRM 分开采购 |

## 玩家光谱：从 SAP 到管家婆

ERP 市场是一个光谱，按公司规模和预算排：

- **SAP / Oracle**：跨国大厂。SAP 1972 年创立于德国，全球五百强的财务供应链多半跑在它上面。实施一个 SAP 项目以百万美元起步，周期以年计。
- **用友 / 金蝶**：国产中坚。用友 1988 年、金蝶 1993 年成立，吃下中国大量上市公司和央国企的份额，产品线从几万块的套件到千万级的项目都有。
- **SaaS 进销存**：聚水潭、管家婆们，服务小微企业和电商卖家，几百块一年，开箱即用。

同一家公司的名字会出现在光谱多个位置——金蝶既卖小微企业版也服务大集团。**选型基本被公司体量锁定**，这不是技术判断题，是预算和组织复杂度判断题。

## 为什么实施比软件贵

行业流传一句老话，普遍认为出自柳传志：「**上 ERP 是找死，不上 ERP 是等死。**」前半句说的就是实施的坑。软件许可费往往只占项目成本的三分之一，剩下全花在「让公司用起来」上：

**第一，流程再造。** ERP 要求全公司按一套标准流程走，但每个部门都有祖传习惯：采购习惯先收货后补单，销售习惯口头答应客户插队。上 ERP 意味着这些习惯全部作废，按系统的规矩来。**改软件容易，改人难**——多少 ERP 项目死在销售总监一句「我就不填这个表单」上。

**第二，主数据。** 同一种混合坚果，采购部叫「混合坚果A」，仓库叫「MX-001」，财务叫「原材料-坚果类」。想一本账记到底，全公司必须用同一套编码、同一个名称。统一编码这个活叫主数据治理，听起来简单，做起来是和每个部门扯皮一个月。

**第三，二开地狱。** 标准产品覆盖不了的个性化需求，就要在 ERP 上做二次开发（二开）。第 01 篇那段对话里的「MES 二开」就是这种活。二开的坑在于：你改的是别人家的核心系统，升级时你的改动可能全部作废；不改，业务又等不了。这是 ToB 开发者最常继承的祖传代码——字面意义上的祖传。

于是催生了一个职业：**实施顾问**。既懂软件又懂业务，驻场帮企业把 ERP 落地，按人天收费。这个职业的存在本身就是 ERP 复杂度的证明——世界上没有「Word 实施顾问」。

## 小结与下篇预告

什么时候需要 ERP？看一个信号就够：**对账开始需要跨部门开会**。库存和销售对不上是小事，采购、销售、财务三本账互相矛盾，人工对账成本超过系统成本，就是时候了。反过来，一本 Excel 能记清的生意，上 ERP 纯属自虐——系统是被问题逼出来的，不是公司身份象征。

三只小鹿最后上了一套国产 ERP 的贸易版，对账会议从每月三天变成十分钟。但新问题马上来了：ERP 管住了货和钱，管不住人——公司扩到五十人，报销审批还靠微信群吼，老板出差三天，积压四十条「收到，批」。下一篇：OA，和一条请假审批背后的流程引擎。
