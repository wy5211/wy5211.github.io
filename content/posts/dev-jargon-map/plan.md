# 开发黑话地图 系列计划

## 背景

- 为什么写：很多开发术语只闻其名不知其实——ERP、CMS、CRM、OA、MES、SaaS、中台……听同事聊"我们在给甲方做一个 MES 二开项目"时完全插不上话。这些名词不来自教程，来自行业（尤其是 ToB 软件行业），搜索引擎给的定义要么是百科式空话，要么是厂商广告。
- 核心诉求：
  1. 每个名词说清"这是个什么东西、给谁用的、解决什么问题"
  2. 把散落的名词串成一张地图——按公司职能分区，看到缩写能自己拆解
  3. 补盲区：不止用户点名的 ERP/CMS，还有容易被问到但没意识到的（POC、UAT、实施、二开、私有化……）
- 文章类型：A（技术类）——但这是**扫盲/地图型系列**，代码占比接近 0，重认知轻实现，延续 backend-map / infra-map 的方法论：**每个系统都是被公司发展的新问题逼出来的**。

## 贯穿案例：三只小鹿的成长史

虚构一家零食品牌「三只小鹿」，从淘宝夫妻店一路长到几百人的品牌公司。每篇文章对应公司的一次成长阵痛——系统是被问题逼出来的：

```
阶段 0：淘宝店，夫妻俩用 Excel + 微信管一切（01）
阶段 1：要做品牌官网和内容营销 → CMS（02）
阶段 2：库存对不上账、三本账打架 → 进销存 → ERP（03）
阶段 3：招销售团队做企业团购，Excel 跟丢客户 → CRM（04）
阶段 4：50 人公司，报销审批靠微信群吼 → OA（05）
阶段 5：自建工厂 + 仓库，订单到发货全链路 → MES/WMS/OMS（06）
阶段 6：上百人，HR 用 Excel 发薪出错、客诉没人跟 → HRM/工单（07）
阶段 7：老板要看"哪个渠道赚钱" → BI/数仓（08）
阶段 8：CIO 选型：买 SaaS 还是私有化定制 → 商业模式黑话（09）
阶段 9：你入职软件公司，参与三只小鹿定制项目 → 需求评审听力考试（10）
```

最后一篇视角切换：从前八篇的"公司视角"（要用什么系统）切到"开发者视角"（怎么接需求做交付），把流程黑话一次串完。

## 阶段划分

- **入门（01-02）**：建立命名规律 + 从最熟悉的 CMS 切入，让读者发现"黑话我其实见过"
- **核心（03-08）**：按公司职能逐区扫荡——钱（ERP）、客（CRM）、流程（OA）、货（MES/WMS/OMS）、人（HRM/工单）、数（BI）
- **进阶（09）**：从"系统是什么"升维到"系统怎么买/怎么卖"——商业模式与部署形态
- **实践（10）**：开发者视角的全流程串讲，收官给"按规模选系统"的组合建议

## 每篇文章大纲

### 01 黑话地图：ERP、CMS 这些缩写是怎么造出来的

- 学习目标：看到任何三字母缩写能拆解；建立"公司职能 → 系统"的映射直觉
- 核心问题：为什么开发圈这么多缩写？它们是什么关系？
- 主线场景：三只小鹿创业之初，Excel 管订单、微信管客服、脑子管库存，一切安好——直到不安好
- 内容要点：
  - 命名套路：领域词 + Management/System/Planning，拆一个会一串
  - 缩写简史本身就是故事：MRP → MRP II → ERP → ERP II（每个都是上一代的营销升级）
  - 一张全家福地图：按职能分区（钱/客/货/人/流程/数据），后续每篇点亮一块
  - ToB vs ToC 一句话入门（为什么这些系统都是 ToB 的）
- 名词卡片：MIS、EAM、DMS、GTM 等周边缩写
- 与前篇关联：无（首篇），结尾抛出"你最可能亲手写的系统：CMS"

### 02 CMS：你正在看的博客背后是什么

- 学习目标：说清 CMS 是什么、边界在哪；WordPress/Headless/自研怎么选
- 核心问题：博客、官网、新闻站，背后是同一类东西？
- 主线场景：三只小鹿要做品牌官网 + 食谱博客，招了个前端，前端问"内容谁来更新？"
- 内容要点：
  - 内容与展示分离——CMS 存在的全部理由
  - 三大件：内容建模（文章/食谱都是"内容类型"）、编辑后台、发布渲染
  - WordPress 为什么能吃下四成网站；插件主题生态
  - Headless CMS（Strapi/Contentful）：前后端分离时代的 CMS，只出数据不出页面
  - 什么时候自研：和 springboot 系列的 CMS 案例互链（那边教写，这边讲是什么）
- 名词卡片：WYSIWYG、DXP、SSG、静态化
- 与前篇关联：用 01 的地图定位 CMS（对外内容区）；主线进入阶段 1

### 03 ERP：公司的大管家，和它臭名昭著的实施

- 学习目标：ERP 管什么不管什么；为什么"上 ERP 找死，不上等死"是行业名梗
- 核心问题：一个词怎么既指财务软件又指工厂系统？
- 主线场景：三只小鹿仓库盘点，账面 1200 箱坚果实际 900 箱；采购、销售、财务三本账对不上
- 内容要点：
  - 先讲进销存（小公司救命稻草），再讲 ERP（进销存的完全体）
  - 演进史：MRP（算料）→ MRP II（加钱）→ ERP（整个公司资源）
  - 核心模块地图：财务/采购/库存/销售/生产，单一数据源是灵魂
  - 玩家光谱：SAP/Oracle（跨国大厂）→ 用友/金蝶（国产中坚）→ 某某进销存（小微企业）
  - 为什么实施比软件贵：流程再造、主数据、员工抵制；"二开地狱"
- 名词卡片：主数据、BOM、财务云、模块化上线
- 与前篇关联：01 的地图点亮"钱"区；02 的官网接了订单后，后端开始乱

### 04 CRM：销售的兵器库

- 学习目标：CRM 管什么；销售漏斗、公海私海这些黑话什么意思
- 核心问题：Excel 也能记客户，为什么要专门系统？
- 主线场景：三只小鹿招了 5 个销售做企业团购（写字楼下午茶），半年后销售离职，客户资料跟着人走了
- 内容要点：
  - 客户全生命周期：线索 → 商机 → 成交 → 复购，每阶段一个系统功能
  - 销售漏斗与预测；公海/私海（客户归属）机制
  - 玩家：Salesforce（祖师爷）、纷享销客/销售易（国产）、SCRM（企微生态，中国特产）
  - 营销自动化（MA）：群发邮件怎么变成"线索打分"
- 名词卡片：Lead、商机、SFA、SCRM、MA、私域
- 与前篇关联：ERP 管"成交后的货和钱"，CRM 管"成交前的客户"——一条线切开

### 05 OA：一条请假审批的旅程

- 学习目标：OA 是什么；钉钉飞书为什么吃掉了这个市场；流程引擎是什么
- 核心问题：发个请假条为什么要用系统？
- 主线场景：三只小鹿 50 人，报销审批靠微信群吼，老板出差三天积压 40 条"收到，批"
- 内容要点：
  - OA 的本质：把"人找领导签字"变成"流程找人"
  - 一条审批流的技术解剖：表单 → 流程节点 → 条件分支（请假 3 天以上才到 HR 总监）→ 归档
  - 流程引擎：钉钉宜搭、飞书审批背后是什么
  - BPM 与 OA 的关系；为什么传统 OA 厂商（泛微、致远）被字节阿里降维打击
- 名词卡片：BPM、工作流、表单引擎、电子签章
- 与前篇关联：前面管的都是"对外生意"（货、客），从这篇开始管"公司内部"

### 06 MES、WMS、OMS：工厂和仓库里的软件

- 学习目标：分清 MES/WMS/OMS/TMS 各管哪一段；制造业软件栈的全景
- 核心问题：为什么工厂程序员的工作和互联网程序员完全两个世界？
- 主线场景：三只小鹿自建工厂，淘宝订单 → 车间生产 → 仓库发货，中间全靠人肉传单，发错货率 3%
- 内容要点：
  - OMS：订单从哪来到哪去，多渠道订单归一
  - WMS：入库、库位、波次拣货、出库——仓库的数字孪生
  - MES：工单、报工、条码、追溯——车间的数字孪生
  - 和 ERP 的关系：ERP 是账，MES/WMS 是现场，账实相符是永恒主题
  - 制造业开发者的日常：和 PLC、扫描枪、老式打印机打交道
- 名词卡片：SCM、TMS、SRM、AGV、WCS、批次/序列号追溯
- 与前篇关联：03 埋的伏笔（ERP 的生产模块）在这里展开成完整工厂栈

### 07 HRM 与工单系统：支撑部门的软件

- 学习目标：HRM/HCM 管什么；工单系统为什么是万能形状
- 核心问题：为什么说"工单系统是 ToB 界的 Hello World"？
- 主线场景：三只小鹿 150 人，HR 用 Excel 算错绩效扣款被全员围观；客服投诉散落在 5 个微信群无人跟进
- 内容要点：
  - HRM → HCM 的名称通胀；招聘（ATS）、考勤、薪酬、绩效各是一摊
  - 工单系统的通用形状：提交 → 分派 → 处理 → 关闭 → 沉淀知识库，客服/IT 支持/售后共用
  - ITSM 与 SLA：为什么 IT 部门最爱说"提个单"
  - 知识库：工单的副产品，客服自助化的基础
- 名词卡片：ATS、HCM、ITSM、SLA、知识库、坐席
- 与前篇关联：05 的流程引擎思想在工单里复现（换个皮）；主线公司进入规模化阶段

### 08 BI 与数据黑话：老板要的大屏

- 学习目标：BI 和报表的区别；指标、维度、数仓这些词的关系
- 核心问题：有了 Excel 透视表，为什么还要花几百万上 BI？
- 核心问题场景：老板问"天猫、抖音、线下门店哪个渠道赚钱？"，运营导了 7 个 Excel，口径对不上
- 内容要点：
  - 报表 → BI 的跃迁：从"看数"到"探索为什么"
  - 指标与维度：同一份销售额的 N 种切法；口径之战（GMV 是含税还是不含税）
  - 数仓/数据湖一句话入门：为什么要先把数据搬家清洗
  - 大屏文化：为什么政府和国企爱大屏
  - 玩家：Tableau/Power BI/FineBI（国产）
- 名词卡片：OLAP、数据看板、同环比、埋点、口径
- 与前篇关联：前面所有系统都是"生产数据"，BI 是"消费数据"——公司数字化的下半场

### 09 SaaS、私有化、中台、低代码：商业模式黑话

- 学习目标：IaaS/PaaS/SaaS 三层能画出来；ToB 项目的商业模式黑话全掌握
- 核心问题：同样是"用软件"，为什么有的月付 99，有的要养一个开发团队？
- 主线场景：三只小鹿 CIO 盘点：CRM 买 SaaS、ERP 私有化、大屏低代码搭——每种的账怎么算
- 内容要点：
  - 云服务三层楼：IaaS（租毛坯房）→ PaaS（租精装）→ SaaS（住酒店）
  - 买断 vs 订阅；SaaS 的"订阅幻觉"
  - 私有化部署：数据敏感行业的执念；ToB 开发者的日常差异（客户内网、老版本浏览器）
  - 中台：从阿里口号到"拆中台"，一个黑话的完整生命周期
  - 低代码/无代码：宜搭、简道云；"程序员要失业了吗"的真答案
- 名词卡片：OP（On-Premise）、多租户、POC、续费率、SaaS 化
- 与前篇关联：前八篇所有系统在这里被重新分类——不是按职能，而是按"怎么卖"

### 10 收官：听懂一场需求评审

- 学习目标：ToB 项目从售前到交付的全流程黑话；开发者在这条流水线上的位置
- 核心问题：新人开发者为什么在第一次需求评审会上像在听外语？
- 主线场景：视角切换——你入职一家软件公司，第一个项目就是三只小鹿的"全渠道订单中台"，参加第一次需求评审会：售前在讲 PPT，产品经理在念 PRD，甲方信息科科长在提"要兼容我们 2015 年的 ERP"……
- 内容要点：
  - 项目诞生记：售前 → POC → 招投标 → 合同（每个词背后是什么动作）
  - 需求流转：PRD → 需求评审 → 排期 → 迭代 → 提测 → UAT → 上线
  - 敏捷黑话：迭代、站会、Story Point、燃尽图——仪式背后的真实目的
  - 甲方乙方：为什么乙方程序员过的和互联网程序员不是一个生活
  - 收官组合拳（反过度上系统视角）：小店只要收银+表格；百人公司标配四件套；集团才谈得上中台
- 名词卡片：售前、POC、招投标、PRD、UAT、验收、维保期
- 与前篇关联：全系列系统名词在本篇的场景里各归其位——这场评审会就是毕业考试

## 系列节奏规划

- 入门（01-02）：先给规律再给最熟悉的例子，读者第 2 篇就该有"哦原来我早见过黑话"的松弛感
- 核心（03-08）：每篇一个职能区，主线公司每篇长大一圈；篇间用"上一阶段的新问题"衔接，避免变成名词词典
- 进阶（09）：视角从"系统本身"升到"商业模式"，为收官的开发者视角做铺垫
- 实践（10）：场景化的黑话听力考试 + 按规模选系统的收官建议（延续 infra-map 收官篇的反过度设计立场）
- 每篇固定元素：开头主线场景 → 名词拆解 → 边界（它不管什么）→ 名词卡片表格 → trade-off（谁在用/什么时候不需要）
