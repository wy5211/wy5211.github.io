三只小鹿自建工厂了。坚果烘制和包装从代工贴牌转成自产，本想省代工费，结果撞上一个新世界：

天猫订单在后台导出打印，纸单交给车间，排产靠车间主任吼；生产完的货搬进仓库，库位全凭老师傅记忆；客户投诉发错货，一查是拣货员拿错了相似包装的 SKU——发错货率 3%，每个月赔进去一部 iPhone。

办公室里的系统（ERP、CRM、OA）在这里全部失效，因为它们管的是**账**，而工厂和仓库要管的是**现场**。这一篇把「货」的三条线拆开讲。

## 先分清三条线：订单、仓库、车间

一张图定位三个系统的管辖范围：

```
【卖】 OMS 订单管理：天猫/京东/抖音/小程序的订单归一、状态跟踪、路由到仓
         ↓ 指导发货
【存】 WMS 仓库管理：收货上架、库位管理、波次拣货、复核出库
         ↓ 要货生产
【造】 MES 制造执行：工单派工、报工、条码采集、批次追溯
```

三个都是「XX Management/Execution System」，第 01 篇的拆词套路继续有效。分别展开。

## OMS：订单从哪来，到哪去

三只小鹿的订单散落在天猫、京东、抖音、自营小程序四个渠道，每个后台一套界面。OMS（Order Management System，订单管理系统）干的活：

- **归一**：四个渠道的订单拉进一个池子，统一数据结构（渠道不同，字段口径五花八门——光是「收货人手机号」有的渠道加密有的不加密）。
- **状态机**：待付款 → 待发货 → 已发货 → 已签收 → 完成/退款，每个状态变化回写到对应渠道。
- **路由**：订单发哪个仓——华北的订单发北京仓，生鲜礼盒只发有冷链的城市。

电商公司的「中台」故事（第 09 篇展开）一半就是从 OMS 长出来的。对三只小鹿这个体量，一个聚水潭就够；做到几千万流水自研 OMS 才开始划算。

## WMS：仓库的数字孪生

WMS（Warehouse Management System，仓库管理系统）的世界观一句话：**仓库里每个货位、每次移动都是数据**。

一个订单在 WMS 里的典型旅程：

```
收货上架：供应商的货到月台，扫码验收，系统分配库位（A-03-02：A区3排2层）
存储：    1000 个库位各记各的货，先进先出（坚果有保质期，这叫批次管理）
波次拣货：系统把 500 张订单合成一个波次，规划成一条拣货路径
         ——拣货员推着车按屏幕指令走，一次拣完 500 单的货，不是一单一单跑
复核出库：扫码核对「货和单是否一致」，这就是消灭那 3% 错发率的地方
```

「数字孪生」这个词在这里不是噱头：系统里的库位图和物理仓库一一对应，盘点变成「拿系统数据和现场核对」而不是「从零数一遍」。大促期间仓库效率的差异，大头就在 WMS 的波次和路径算法上——同样的仓库和人力，好的拣货路径能多出一倍的发货量。

再往里一层还有 **WCS**（仓库控制系统）对接自动分拣线、**AGV**（自动搬运机器人）的调度——那是自动化立体仓的世界，三只小鹿暂时用不上，但你会在 WMS 厂商的 PPT 里频繁看到。

## MES：车间的数字孪生

MES（Manufacturing Execution System，制造执行系统）管生产现场。三个核心概念：

**工单**：ERP 的生产计划下达到车间，变成「本周生产每日坚果 30 万袋」的工单。工单是 MES 的基本单元。

**报工**：每完成一道工序——烘制、调味、包装——工人或机器扫码上报产量和良品数。实时知道进度，而不是等下班后车间主任汇报。

**批次追溯**：这是 MES 的杀手锏。每批原料一个批次号，每个成品记录「用了哪几批原料、哪条产线、哪天生产」。三只小鹿某天接到投诉「一袋坚果有哈喇味」：没有 MES，全渠道召回同批次产品要两周；有 MES，两小时定位那批货的原料批次和全部流向——**召回范围从「全部」缩小到「精确批次」，省下的是真金白银和品牌命**。

MES 和 ERP 的关系值得单说：ERP 第 03 篇讲过有生产模块，但那只是「计划」——排产算料。真到了车间，设备、工人、良品率的现实复杂度远超计划层的想象。行业里管这个分层叫：**ERP 管账（计划层），MES 管现场（执行层），再往下是 PLC 和传感器（控制层）**。账实相符——ERP 说造了 30 万袋、车间实际报工 29.7 万袋——中间的 gap 就是两个系统对不上的痛苦，也是无数集成项目的由来。

## 制造业程序员的日常

第 01 篇说过写 ToB 的程序员占大多数，其中制造业（MES/WMS 这类）又是大宗。他们的日常和互联网程序员是两个世界：

- 对接的「用户」是**扫描枪、标签打印机、PLC、地磅**——设备协议文档比需求文档还难读
- 工厂网络可能和办公网物理隔离，部署要**驻场**，出差是常态
- 车间电脑跑着十年前的 Windows，浏览器兼容性问题是日常
- 但业务复杂度高、行业壁垒深——一个懂工艺流程的开发者，非常难被替代

这份工作不性感，但稳。

| 名词        | 全称                             | 一句话定义                         |
| ----------- | -------------------------------- | ---------------------------------- |
| OMS         | Order Management System          | 订单归一、状态跟踪、发货路由       |
| WMS         | Warehouse Management System      | 仓库的数字孪生：库位、波次、出入库 |
| MES         | Manufacturing Execution System   | 车间的数字孪生：工单、报工、追溯   |

| 工单 / 报工 | Work Order / Reporting           | 生产任务单 / 工序完成上报          |

## 小结与下篇预告

什么时候需要这三个系统？分界线很清楚：**订单渠道多于两个，Excel 和平台后台管不过来，上 OMS；仓库多于一个人管得过来的规模、或者错发率成为成本，上 WMS；有了自己的产线和批次召回风险，上 MES**。三只小鹿最后上了聚水潭（OMS+WMS 一体），MES 因为只有一条产线暂缓——系统是被问题逼出来的，产线不够多就是问题还不够大。

货的线齐了。下一篇回到人和服务：公司一百五十人了，HR 用 Excel 算绩效，一次公式错误让全员围观；客诉散落五个微信群没人跟进。HRM 和工单系统——后者的那句行业玩笑是：「工单系统是 ToB 界的 Hello World」。
