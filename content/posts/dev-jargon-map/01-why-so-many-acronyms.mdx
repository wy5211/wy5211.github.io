周一早上，你作为新入职的后端开发，参加第一个项目会。会开到第十分钟，你开始怀疑自己是不是上了个假班：

> 「这个 ToB 项目是给甲方做 MES 二开，原厂接口不开放，售前答应的 POC 下周就要演示。需求侧 PRD 还没评审完，甲方信息科说 UAT 环境得等他们把 ERP 的主数据同步打通……」

每个字你都认识。连起来，一句都听不懂。

这不是你的问题。这些词压根不来自编程教程，它们来自一个行业——**ToB 软件**（卖给企业的软件）。这个行业沉淀了五十年的名词，从业者默认你懂，教程又默认不需要教，于是形成了这么一片没人领你进去的黑话区。

这个系列就是那张地图。和博客里的[部署基础设施地图](/posts/infra-map/01-from-code-to-online)一样，我们先不深入任何单个系统，只做一件事：**把每个名词钉在它该在的位置上**——它管什么、被什么问题逼出来、你一般什么时候才会真的碰到它。

## 先破解一半：造词套路

这些缩写看着吓人，其实是流水线产品。拆开看：

```
ERP = Enterprise（企业） + Resource（资源） + Planning（计划）
CMS = Content（内容） + Management（管理） + System（系统）
CRM = Customer（客户） + Relationship（关系） + Management（管理）
WMS = Warehouse（仓库） + Management（管理） + System（系统）
HRM = Human（人） + Resource（资源） + Management（管理）
MES = Manufacturing（制造） + Execution（执行） + System（系统）
```

规律很明显：**领域词 + Management/System/Planning 的排列组合**。中间那个词几乎永远是 Management，结尾是 System 还是 Planning 看厂商心情。翻译成中文，全都是「XX 管理系统」——名字朴素得让人失望，但这就是真相。

所以下次撞见陌生缩写，先别慌，拆了它：

- **DMS**？Dealer Management System，经销商管理系统（汽车厂管 4S 店的）
- **TMS**？Transportation Management System，运输管理系统（管货车调度的）
- **SCM**？Supply Chain Management，供应链管理

拆完还不认识？那大概率是领域词不熟（比如不知道 MES 的 Manufacturing 指车间制造），这恰恰说明你缺的是行业知识，不是智商。本系列后半段会把常见的领域词全部过一遍。

## 再破解另一半：一半是技术，一半是营销

光会拆词还不够，你还得知道这些词是怎么来的。讲一个行业最经典的故事——ERP 这个词的诞生：

**1960 年代**，美国的工厂有个迫切问题：生产一批饼干，到底要买多少面粉、多少糖？买多了积压资金，买少了停工待料。于是有了 **MRP**（Material Requirements Planning，物料需求计划）——一个根据订单和配方倒推采购清单的程序。很实在的东西。

**1980 年代**，MRP 的功能越滚越多，从算料扩到排产能、算财务。厂商不想放弃 MRP 这个已有知名度的缩写，于是新一代产品叫 **MRP II**——同样的三个字母，意思从「物料需求计划」变成了「制造资源计划」。这是软件行业冷幽默的巅峰：换汤不换药，连药瓶都不换，只在瓶子上刻了个 II。

**1990 年**，分析机构 Gartner 觉得这套东西的野心已经不止于工厂，覆盖整个企业的资源了，得造个新词做区隔——**ERP** 诞生。注意，ERP 刚出现时更多是个**营销概念**：厂商们需要一个新的、更大的词来卖升级。

这个故事值得记住，因为它揭示了黑话的另一半真相：**新名词往往不是新东西，是老东西的重新包装**。这个词粉逻辑到今天都没停——ERP 之后有 ERP II，CRM 之后有 SCRM，CMS 之后有 DXP。遇到新词先问一句「它和它的前辈差在哪」，能避开大部分雾里看花。

## 一张职能地图：公司有多少种职能，就有多少种系统

套路和来历都清楚了，现在上主菜：这些系统之间的关系。

答案简单得出人意料——**它们不是技术上的关系，是组织上的关系**。一家公司有多少种独立的职能，就长出多少种管理系统。按职能分区，整个黑话世界可以摆成一张地图：

| 职能分区             | 代表系统           | 管什么               | 哪篇展开 |
| -------------------- | ------------------ | -------------------- | -------- |
| 对外内容             | CMS                | 官网、博客、新闻稿   | 02       |
| 钱（进销存/财务）    | ERP                | 采购、库存、销售、账 | 03       |
| 客（客户/销售）      | CRM                | 线索、商机、成交     | 04       |
| 内部流程             | OA                 | 审批、请假、报销     | 05       |
| 货（生产/仓储/订单） | MES、WMS、OMS      | 车间、仓库、订单履约 | 06       |
| 人与支持             | HRM、工单系统      | 招聘薪酬、客服 IT    | 07       |
| 数（分析决策）       | BI                 | 报表、指标、大屏     | 08       |
| 怎么买怎么卖         | SaaS、低代码、中台 | 商业模式和部署形态   | 09       |

这张表是全系列的目录。用法不是背下来，而是**以后撞见任何一个系统名词，先问它管公司的哪个部位**——位置感有了，细节随时可以补。

## 贯穿案例：三只小鹿

词典式罗列是这类文章最常见的死法。为了不重蹈覆辙，整个系列用一家虚构的公司当主线：**三只小鹿**，一个零食品牌。

它的起点非常小：一对夫妻开的淘宝店，卖坚果和果干。这个阶段的「信息系统」长这样：

```
订单管理：一个 Excel，妻子维护
客户服务：一个微信，丈夫回复
库存管理：两个人的脑子，以妻子的为准
财务：另一个 Excel，月底对一次账，经常对不上
```

注意一个反直觉的事实：**这个阶段一个系统都不需要，而且运转得挺好**。记住这一点，它比后面登场的所有系统都重要——系统是被问题逼出来的，不是公司标配。三只小鹿每长大一圈，就会撞上新问题，每篇文章解决一个：

- 官网和内容营销做起来，内容怎么管？（CMS）
- 仓库对不上账、三本账打架（ERP）
- 销售团队跟丢客户（CRM）
- 审批靠微信群吼（OA）
- 自建工厂后人肉传单（MES/WMS/OMS）……

到第 10 篇，视角会切换到你自己：你入职一家软件公司，参与三只小鹿的定制项目，用一场需求评审会把全系列黑话串成听力考试。

## 为什么开发者躲不开这些词

最后一个问题：我又不去传统行业，学这个干嘛？

看一组现实：**全世界写代码的人里，写 ToB 软件的是大多数**。微信、抖音、淘宝这类直接给个人用的 App 叫 ToC，是少数派；更多的程序员在写 ERP 二开、银行核心系统、政府信息化、工厂 MES、医院 HIS——这些词你接下来会逐一认识。尤其在中国，大量的软件岗位存在于行业软件公司和外包公司里。

但互联网是 ToC 程序员的声音塑造的：教程、博客、面试题都在讲 ToC 的技术栈。于是形成了错位——**岗位在 ToB，教材在 ToC，黑话没人教**。这个系列就是补这个缺口的。

（补一个最小定义：ToB = To Business，卖给企业，采购走流程、决策者和使用者不是同一批人；ToC = To Consumer，卖给个人，下载即用。这两个词的深层差异第 09 篇展开。）

| ------------ | ------------------------------------------ | --------------------------------------------- |

| MIS          | Management Information System              | 管理信息系统，所有「XX 管理系统」的学名       |
| MRP / MRP II | Material / Manufacturing Resource Planning | ERP 的前身：算物料 / 算制造资源               |

## 这张地图不管什么

照例给边界。以下名词**不在**这个系列范围内：

**技术架构类**：微服务、网关、消息队列、服务注册发现——这些是「一个系统内部怎么搭」的词汇，属于技术侧。[部署基础设施地图](/posts/infra-map/01-from-code-to-online)覆盖了它们和运行环境的关系。

**具体厂商操作**：SAP 怎么配、Salesforce 怎么用——本系列讲概念地图，不教操作，就像你不需要会开叉车也可以看懂仓库平面图。

下一篇，从你大概率已经亲手写过、却没意识到它有名字的系统开始：CMS。你见过的每个博客、每个公司官网的新闻页，背后都是同一类东西——包括你现在正在读的这个博客。

## 小结与下篇预告

这一篇只建立两个反射：看到三字母缩写先拆词（领域 + Management/System），拆完问它管公司哪个部位。再加一个世界观：黑话一半是技术演进，一半是营销包装，新词先问「和前辈差在哪」。

下一篇：三只小鹿要做品牌官网了。招来的前端工程师干了一周就发现不对劲——每次发新闻都要找他改代码。内容管理系统（CMS）就是被这件小事逼出来的，而你随手能写的博客程序，其实就是它的最小形态。
