墨记打开一篇带五十张图片缓存的笔记，窗口白屏三秒。这三秒里用户点了七八次滚动条，毫无反应，然后所有积压的滚动一起跳过去。你查了半天，罪魁是一行 `JSON.parse`：那篇笔记的本地缓存有 40MB，解析要三秒。

这三秒里程序死了吗？没有。CPU 在拼命干活，解析一结束界面立刻恢复。它不是坏了，是忙。忙到你点不动它。

这篇要把「忙到点不动」这件事拆开，拆出全系列的地基概念：线程。写 Electron 的人对它其实有大量体感，只是没人把这些体感和这个词对上号。

## 两种卡，你早就分得清

写 Electron 的你，对两种卡都不陌生。

第一种：某个窗口白屏或冻结，别的窗口好好的。你心里有数，渲染进程被长任务占住了，只冻那一个窗口。

第二种：整个应用所有窗口一起没了反应，连标题栏都拖不动。这回是主进程被占住了，比如你在主进程里同步读了个大文件，或者同步跑了一次压缩。

两种卡，波及范围差很远。差在哪？差在被占住的那个东西，是进程，还是进程里的线程。这两个词你天天挂在嘴边，但值得花一整篇讲准，因为后端世界的单线程、多线程、锁、分布式锁，全都押在这两个词上。

## 进程：一栋一栋独立的房子

Electron 的最小结构你熟：一个主进程，加上每个窗口一个渲染进程。在操作系统看来，它们是真实的、独立的进程，各有各的内存空间，互相不通。

```
操作系统
├─ 主进程（管窗口生命周期、系统 API、进程间通信）
├─ 渲染进程 A（窗口 1：跑 JS + 画界面）
└─ 渲染进程 B（窗口 2：跑 JS + 画界面）
```

互相不通带来一个好处：隔离。A 窗口卡死、崩溃、内存泄漏，B 窗口照常工作。不是因为 B 命好，是它俩连一块共享内存都没有，A 想连累 B 都找不到物理通道。

你天天享受进程隔离的红利，只是没这么叫它而已。

## 线程：房子里干活的人

进程自己是不会跑代码的。跑代码的，是进程里面的线程。一个进程至少有一根线程，也可以有很多根。

关键来了，这也是渲染进程卡顿的真相：渲染进程里，跑你的 JS 和画界面，是同一根线程，叫主线程。

```js
// 渲染进程主线程：解析完之前，界面一帧都不会画
const note = JSON.parse(rawCache); // 40MB 的缓存，三秒
```

`JSON.parse` 跑三秒，这三秒这根线程就被你占着，而画界面的也是它。界面不是坏了，是负责画界面的人没空画。那用户点的鼠标呢？操作系统收到了，作为事件放进队列，排队等这根线程忙完来处理。三秒后解析结束，队列里积压的事件被一口气处理掉，所以滚动会猛跳一下。

主进程同理，而且更惨：它那根线程要伺候所有窗口（窗口的创建销毁、菜单点击、和各渲染进程之间的消息传递），被你那个同步大文件读写占住，所有窗口就一起冻结。

到这里可以给出全系列反复使用的一句话定义了。线程，是进程里真正执行代码的那个人。卡，就是这根线程在忙别的，没空理你。

## 四个核，是什么意思

一根线程，同一时刻只能执行一段代码。这不是 Node 的限制，是线程这个概念本身的定义。

那大家买电脑都看的四核、八核呢？意思是这块 CPU 同一时刻最多让四根、八根线程真的在同时跑。所以「多线程」吸引人的地方很直白：人多好办事，四根线程能把四个核吃满。麻烦也同样直白：多个人同时改一份东西，会打架。打架的具体现场在 06 和 07，这里先按下不表。

## 「Node 是单线程的」，从此听准

这句话准确的意思是：你的 JS 代码，只跑在一根线程上。

注意主语，是你的代码。Node 进程里其实还有别的线程：你用异步的 `fs.readFile` 读大文件时，真正在磁盘上干活的，是内部线程池里的线程；垃圾回收也有自己的线程。只是这些线程不归你的代码指挥，你摸不到它们。

Java 和 Go 说的多线程是另一回事：你的代码天然就跑在多根线程上，一个请求分一根线程去处理，是 Java Web 服务多年的默认做法，你还可以自己开新的。

同一份逻辑，落在单线程世界和多线程世界，会遇上的 bug 完全是两套。这就是这个系列存在的理由：把两套世界各走一遍。

## 为什么你到现在都没有体感

回头想想，前端环境其实给了你两个保护罩。

一个是单线程。浏览器里你的 JS 没有对手，不存在另一根线程插进你的两句代码中间执行。后面会看到，Java 世界有一大类 bug，病因就是「有另一根线程插了进来」。

另一个是进程隔离。一个标签页卡死，别的标签页照常刷视频。

服务端这两个罩子都没有了：你的代码旁边是成百上千个并发请求；等你写多了，还可能是几台机器同时在跑你的代码。卡与抢，都会找上门。

## 名词卡片

| 名词   | 英文        | 一句话                                                       |
| ------ | ----------- | ------------------------------------------------------------ |
| 进程   | process     | 操作系统里一栋独立的房子，有自己的内存，别人进不来           |
| 线程   | thread      | 房子里真正执行代码的人，一个进程里可以有一个或很多个         |
| 主线程 | main thread | 进程里第一根、通常也最忙的线程；渲染进程里它既跑 JS 又画界面 |
| 阻塞   | blocking    | 一件事把线程占住，结束之前线程干不了别的                     |

## 什么时候不用管它

纯本地的 Electron 小工具、写给自己用的脚本，卡三秒就卡三秒，用户是你自己。线程这个概念开始值钱，是你的代码要同时伺候很多人的时候。

墨记正好走到这一步。公司决定做云同步，一千个客户端要同时连一个服务，而这个服务你打算用 Node 写。它只有一根线程，一千个客人，扛得住吗？下一篇先不急着回答，先把「单线程和多线程到底差在哪」这张地图画出来，你会看到差别不在平时，在出事那一刻。
