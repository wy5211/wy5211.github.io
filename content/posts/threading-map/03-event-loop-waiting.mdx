[上一篇](/posts/threading-map/02-single-vs-multi-map)画完地图：差别不在平时，在某个请求把线程占住的那一刻。也留了一个悬案：一个店员怎么同时招呼一百桌。这篇拆这个魔术。

先看现场。墨记同步服务上线第一周，后台监控显示：一千个客户端同时在线，平均每个客户端每分钟拉一次增量，Node 进程的 CPU 占用百分之五。

你的第一反应和我当时一样：监控坏了吧。一千个客人，一个店员，他才用了百分之五的力气？

监控没坏。这一千个请求，几乎全部处在同一个状态：等数据库回话。而等，不占线程。

## await 到底干了什么

把墨记的一个同步请求摊开，看那根唯一的线程在里面的行程：

```js
// 这段代码跑在那根唯一的线程上
const user = await db.query("select * from users where ..."); // ①
const notes = await db.query("select * from notes where ..."); // ②
return json(notes); // ③
```

走到 ①，线程干的事是：把 SQL 发给数据库，登记一句「结果回来叫我」，然后离开这个请求，回柜台接下一个。数据库在那边花 40 毫秒查数据，用的是数据库自己的线程，跟你没关系。你的线程这 40 毫秒在招待别的客人。

数据库回话了，这个请求带着现成的结果重新排队，排到了就从 ① 的下一行继续，走到 ②，再撒一次手。

这就是服务员的行为：点完单把单子递进后厨，转身去下一桌，而不是杵在出菜口盯着锅。菜好了响铃，他手头方便了再来上菜。

所以「同时招待一百桌」的真相是：任何时刻，他手上只有一桌的活，其余九十九桌都在后厨锅里或者排队等他。没有分身，只是没有一分钟花在干等上。

## 事件循环，你其实已经会了

让这一切转起来的机关叫事件循环，一句话讲完：一根线程反复转圈，看谁等的消息到了，就接着处理谁。

写前端的人对这套一点都不陌生。浏览器里你写 `setTimeout`、写 `Promise.then`、等用户点击，靠的是同一个循环。`await` 更是原样平移：await 后面没写的代码，就等于你当年手写的回调函数，消息到了才执行。

Node 只是把这套循环从「等用户点击、等定时器」扩展到了「等数据库、等磁盘、等网络」。会写前端的你，服务端异步的心智模型是现成的。

循环内部怎么排优先级（微任务宏任务谁先谁后、六个阶段各干什么）不影响今天的结论，想深究看 [nodejs-core 的事件循环篇](/posts/nodejs-core/03-event-loop)。

## 一根线程能挂多少个等待

算一笔账，就知道单线程的容量从哪来。

一个等待中的请求，占用的是什么？一份「回来叫我」的登记信息，加上这个请求的上下文，拢共几 KB 内存。不占 CPU，更不占别的线程，因为根本没有别的线程。

挂一万个等数据库的请求，成本是几十 MB 内存。这是 Node 一个进程敢面对上万连接的底气。

同一件事放到「一个请求一根线程」的 Java 老写法上，账就不一样了：一根线程按默认配置预留 1MB 栈，一千个并发请求就是一千根线程，光栈就按 GB 算内存，CPU 还要花功夫在这些线程之间来回切换。这个账后来逼出了两件事：Go 把「店员」做得极轻（协程，几 KB 一个，所以一家店能雇几十万个），Java 21 也交出了虚拟线程，思路殊途同归。语言在变轻，但「等不占线程」这个朴素的观察，Node 从第一天就在用。

## 坏消息也在这套魔法里

魔法有一个前提，上一篇埋过：所有客人都在等。

只要有一个客人在算，比如要你当场算一个压缩、解一段大 JSON，转圈的这个人就被按住了。转圈一停，那一千个「等数据库回来叫我」的登记，一个都处理不了，哪怕数据库早就把数据送回来了。

百分之五 的 CPU 是一千个客人在等的数字。某个数字冲到百分之百并且钉在那里的时候，就是事故。墨记的事故在下一篇，五百张照片，一百秒，全站超时。

| 名词     | 英文       | 一句话                                           |
| -------- | ---------- | ------------------------------------------------ |
| 事件循环 | event loop | 一根线程反复转圈：看谁的消息到了，接着处理谁     |
| IO 密集  | IO-bound   | 活的大头在等数据进来出去，CPU 大部分时间闲着     |
| 回调     | callback   | 「好了叫我」时被调用的那段代码，await 是它的糖衣 |
| 协程     | coroutine  | 极轻量的「店员」，几 KB 一个，Go 语言的主打      |

## 什么时候不用管它

低并发的内部工具、个人项目，你怎么写都行，哪怕全用同步阻塞，卡的是你自己。这套模型开始值钱，是并发客人数到几百以上的时候。
